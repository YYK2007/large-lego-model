# Pinned dynamic catalog increment

A design can carry `catalog: CatalogManifest` with actual flattened LDraw meshes, explicit ordinary upright stud/underside sites, exact produced part/color IDs and source URL/hash/license/author metadata. `resolveCatalog(manifest)` combines that immutable snapshot with existing geometry. No process-global registration or new source-code entry is needed for an eligible part. Same-ID conflicting snapshots are rejected. New client submissions must pass `verifyCatalogManifest`, which compares them with server-resolved snapshots; a client-supplied hash alone is not evidence.

Run `node --import tsx scripts/check-catalog.ts --budget-ms 45000 --limit 48` from the repository root. Configure `REBRICKABLE_API_KEY` locally first; this command never prints it. The public Rebrickable bulk index needs no key; exact colors/identity use its API. The initial LDraw complete library is about 146 MB. Downloads and resolved records are ignored under `data/catalog/`. A fresh checkout may consume its first allowance fetching shared assets and fill colors. Run again to continue; budget exhaustion returns verified cached/partial successes and a warning. User cancellation aborts. Customize `--query 'Wedge Plate|Brick Arch'` or `--parts 3021,54200`; explicit IDs supplement search. No Gemini calls occur.

Observed warm-up on 2026-10-10: 64,796 discoverable IDs, 58 usable types (36 existing + 22 dynamically imported), 176 nontransparent colors with mapped LDraw IDs. Of 65 sampled candidates, 27 were supported including existing parts and 38 were rejected with recorded reasons. This is evidence of the importer, not a permanently complete catalog or live marketplace stock check. Supported imports include plates, wedges, curved and cheese slopes, arches and round tiles. Search covers the bulk index, not a curated subject list.

Meshes are flattened from official LDraw geometry and retain exact source polygons and actual stud meshes. LDCad Shadow Library metadata is pinned to a repository revision. Upright radius-6 LDU stud/receiver semantics are admitted on the canonical lattice; unsupported snaps are retained but never used. SNAP_CLEAR, nested snap includes, fixed-color/printed subparts, unavailable exact LDraw mappings, non-lattice geometry/contacts and unsupported mate types remain ineligible. Some shapes have additional unsupported connector metadata while their verified upright mates remain usable.

Collision/insertion checks reserve a conservative upright body envelope; a documented 1e-4-stud (0.8-micrometer) boundary tolerance accounts for numerical tessellation noise without changing mesh vertices. Actual protrusions above that tolerance still round the reservation outward; they do not perform exact concave mesh collision or permit threading pieces through an imported arch. Four yaw rotations, grounded connection graphs, and existing checked insertion ordering apply. Arbitrary rotations, sideways/hinge/clip/bar/axle mates and load-bearing physics remain unimplemented. Colors use catalog RGB; transparency is excluded and metallic/pearlescent finishes are not simulated. Catalog existence and historic produced colors do not establish current stock, price, or purchasability.

Web, assembly diagrams, PDF, USDZ and LDraw use the pinned mesh/sites. Imported definitions are embedded in the LDraw MPD export so later library changes cannot change that file. Source assets retain LDraw author/CC BY attribution and LDCad CC BY-SA metadata. Primary sources: [Rebrickable API](https://rebrickable.com/api/), [Rebrickable downloads](https://rebrickable.com/downloads/), [LDraw library](https://library.ldraw.org/), [LDCad shadow library](https://github.com/RolandMelkert/LDCadShadowLibrary).

Verification for this increment: the focused dynamic-catalog and resolver suites pass 13 tests, including all-yaw canonical/native/instanced geometry, archived batched USDZ triangles/normals, MPD source-space transforms, PDF names/credits, exact receiver rejection, stored-revision preservation, produced-color admission, forged-manifest rejection, bounded partial discovery and user cancellation. A subsequent 64-test renderer/model/manual/native group and TypeScript/Vite build passed; 42 relevant tests were repeated after the final PDF name-layout and instruction-copy corrections. Prior trusted snapshots remain admissible after numerical envelope correction; conflicting same-ID manifests still cannot silently replace each other.

Local visual/export evidence is under `output/catalog-import/`: `varied-design.json`, `varied.png`, `varied-parts.png`, `varied-step.png`, `varied.pdf`, `varied.usdz`, `varied.mpd` and `varied.csv`. The 64-piece connected test fixture uses six imported families and seven assembly steps. Its 11-page PDF parts/placement pages were rendered and inspected. The actual 4,936,148-byte batched USDZ archive was checked: 3 material meshes preserve all 64 bodies, 610 stud meshes and 50,868 triangles from the canonical renderer. This is a local artifact check, not an iPhone/device test or a generated-subject likeness claim. The later shared cache contained 30 imported types (66 total); that growth came through the same importer, without source-code IDs.
